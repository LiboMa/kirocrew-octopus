# Workflow Studio 操作指南

公开文档入口：[架构基线](BASELINE.md)与[下一阶段计划](../PLAN.md)。
三张基线 SVG 随源码分发；客户案例原始报告保留在原本机 PoC。
本文操作适用于现有 macOS 单用户工作台。EC2 远程访问与多人权限属于后续实验。


更新：2026-10-08。页面地址：`http://127.0.0.1:8917/`。
双击 `Workflow Studio.command` 启动；已打开的页面刷新即可加载界面更新。

## 先选流程，再看本次开发

```text
左栏：工作流 → Session
        ↓ 选择本次开发
中间：任务进度 / 执行记录 / 状态报告
        ↑ 点击任务
右栏：这个 Session 的 Tasks
```

点击工作流名称可以展开或收起它的 Sessions；旁边“编辑”打开三步向导。
Session 行只显示需求摘要、创建时间、版本和任务完成数。
搜索支持工作流名称、需求和完整 Session ID。

- **新建工作流**：左侧蓝色按钮。创建独立草稿，再定义任务、工具、模型和 Effort。
- **新 Session**：选择已有 Session 后，点击中间工具栏“＋ 新 Session”。
  填写新需求，确认开始后建立独立运行。使用当前编辑配置；有草稿时先保存新版本。
- **切换 Session**：点击左侧列表。右侧 Tasks 和中间状态一起切换。
- **查看 Task**：点击右侧任务、中央步骤或报告中的任务行。
  详情内可复制完整 Task ID、查看执行记录、编辑下一版任务。
- **编辑下一版**：当前 Session 的配置固定不变，修改用于下一次运行。

列表中省略长 ID 是为了易读。完整 ID 仍保留在详情、复制操作、执行记录和导出包中。

## Session 操作只保留两处入口

**单个 Session**：中间工具栏“Session 操作”菜单。

| 操作 | 效果 |
|---|---|
| 导出 Session | 下载原生对话、冻结工作流、任务证据和开发文档 ZIP |
| 归档 Session | 从工作台常规列表隐藏；原对话、运行和产物保留 |
| 恢复 Session | 已归档 Session 的菜单自动变为“恢复” |
| 复制 Session ID | 复制完整运行身份，方便定位和报告问题 |

**批量操作**：左栏点击“管理”，显示勾选框、导出和归档按钮。
选择完成后点击“完成”收起管理工具；搜索、筛选和工作流折叠继续可用。
一次导出或归档支持 1–20 个 Session。

在“归档”筛选中可以查找已归档 Session 和已删除工作流。
归档不停止原生任务。删除工作流使用可恢复标记，不删除历史 Sessions 或版本文件。

## 在编辑器中删除工作流

点击工作流旁的“编辑”，在目标页点击“删除工作流”。编辑器内会显示固定的确认面板，
列出工作流名称、ID、版本和影响范围；点击“确认删除”后才提交操作。

- 点击“取消，返回编辑”、右上“返回编辑”或按 Esc，会保留草稿、滚动位置和编辑器。
- 确认面板不会被后台刷新或点击遮罩自动关闭，也不使用浏览器系统弹窗。
- 提交期间按钮锁定，连续点击不会重复发送。接口报错会留在面板内，可重试或取消。
- 已保存工作流仍采用可恢复删除：原 Session、版本和运行记录保留，可在“归档”中恢复。
- 未保存草稿只从当前浏览器移除；删除后返回已有工作流，不自动创建替代草稿。

## 状态报告与颜色

中间有三个视图：

- **任务进度**：顺序步骤、所选任务、任务动态与交付入口。
- **执行记录**：真实后端、请求模型、实际模型、Effort、原生 Task / Session ID 和返回结果。
- **状态报告**：已交接、执行中、待处理、待执行的数量，逐任务状态和已报告耗时。
  “原始 JSON”保留机器可读报告入口。

| 颜色 | 意义 |
|---|---|
| 绿色 | 已核对并接受交接 |
| 蓝色 | 正在执行 |
| 橙色 | 待授权、待核对、交接条件未通过 |
| 红色 | 执行失败 |
| 灰色 | 待执行或待调度 |

状态同时有文字，不依赖颜色判断。上方和报告中的每一段代表一个 Task。
**完成率仅按已交接任务数计算**。正在执行的流动效果不是模型内部完成百分比。
“待处理”汇总待授权、待核对、交接未通过和失败任务；父会话权限请求另外注明，不冒充某个子 Task 的权限。

实时反馈：

- 执行中的段有轻微流动效果。
- Task 状态发生变化时，动态行短暂高亮；相同状态的轮询不会重复闪烁。
- 页面请求失败、Gateway 不可达或 15 秒未收到新快照时，显示“同步暂停”，停止运行动画。
- 历史状态继续可读；原生接口返回 404 等原因会显示在报告内。不会据此删除 Session 或标记完成。
- 系统开启“减少动态效果”时，关闭界面动画。

耗时有两种口径：“已运行”使用原生任务报告的 elapsed；
“至交接”计算从原生启动到接受交接的间隔，包含等待核对的时间。
缺少时间证据时显示“耗时未报告”，不推测。

## 左右栏拖拽

桌面上拖动两侧分隔线，中间开发区域会自动适配。
宽度保存在当前浏览器，刷新后恢复。

| 操作 | 效果 |
|---|---|
| 拖拽分隔线 | 调整对应侧栏宽度 |
| Tab 聚焦分隔线，按左右键 | 每次移动 10px |
| Shift + 左右键 | 每次移动 40px |
| Home / End | 调到该栏允许的最窄 / 最宽范围，仍为中间内容保留空间 |
| 双击分隔线 | 恢复该栏默认宽度 |

窗口宽度不超过 1000px 时关闭拖拽，Tasks 通过上方按钮展开。
手机宽度下 Sessions 也改为滑出侧栏，避免挤压开发状态区域。

## 名称与版本

工作流名称必须唯一。以下视为同名：

```text
Review Workflow
review   workflow
Ｒｅｖｉｅｗ　Ｗｏｒｋｆｌｏｗ
```

后端规范化全半角、空白和大小写，拒绝隐藏控制字符。
新建、复制、模板、导入和采用生成草稿时，会建议 `名称 (2)`、`名称 (3)` 等未占用名称。
手动输入重名会提示；保存接口在写入锁内再次检查，覆盖 Web、Chat 命令和文件保存路径。
两个同时打开的页面不能用不同 ID 抢占同一名称。

已删除工作流的名称仍保留，避免恢复时冲突。可以恢复并编辑原工作流，或为新工作流换名。
同一个 Workflow ID 可以保存多个版本；历史运行保留旧版本名称和配置，不重写历史快照。

## 数据存放与备份

本版保留现有文件持久化，没有引入 SQLite，也没有迁移历史 Session：

| 内容 | 存放位置（相对 PoC 目录） |
|---|---|
| 最新工作流的可编辑文件 | `workflows/*.json` |
| 权威版本历史与删除标记 | `state/workflow-versions/` |
| Session 快照、需求、产物、交接证据与归档标记 | `state/runs/workflow-*/` |
| 意图生成记录 | `state/workflow-designs/` |
| 未保存的向导草稿、折叠状态、栏宽 | 当前浏览器 localStorage |
| 原生对话与工具私有状态 | 由 KiroCrew 和各 Coding 工具管理 |

当前规模下，版本文件、文件写入锁、临时文件替换和运行快照校验足以支撑此次功能。
这不等同于跨文件事务或完整灾难恢复。浏览器草稿也不是服务端备份。

迁移或备份前，导出重要工作流和 Session；完整迁移还需保留运行工作目录及 KiroCrew 自身数据。
Session ZIP 是对话与证据包，**不包含整个代码工作目录或全部工具私有上下文**。

后续若需要大量元数据查询、多用户并发或跨多项元数据的原子操作，再引入 SQLite 元数据层。
届时仍应保留现有版本与产物的导入、导出和恢复能力。
