## 编辑与删除交互修复

- 删除 / 恢复改为编辑器内部确认面板，移除浏览器 `confirm()` 依赖。
- 修复确认闪现、误关闭路径；取消和 Esc 保留编辑内容与位置。
- 固定待操作工作流的 ID / 版本，提交期间防重复点击，错误留在面板中展示。
- 修复删除未保存草稿后立即生成新草稿的问题。
- 在独立无界面浏览器验证确认稳定、取消、后台刷新、删除 / 恢复、失败重试和窄屏显示。
- 已有工作流删除语义保持为可恢复删除，历史 Session 与快照保留。

## 本次变化

- Session 管理简化为单会话菜单和按需打开的批量管理模式；工作流可折叠。
- 增加“＋ 新 Session”；保留归档、恢复、原生导出与完整 ID 复制。
- 紧凑 Task 列表突出名称、工具和状态；详情中查看证据、复制 ID、编辑下一版。
- 状态报告加入数量概览、逐任务状态、已报告耗时和原始 JSON 入口。
- 蓝白主题配合绿、橙、红、灰状态；执行段流动、真实状态变化高亮。
- 断连、快照超过 15 秒或系统减少动态效果设置会停止运行动画，不模拟完成率。
- 左右侧栏支持拖拽、键盘调整、双击复位和宽度保存，窄屏自动适配。
- 工作流名称统一规范化、在同一写入锁内保证唯一；导入、模板、复制和生成草稿建议可用后缀。
- 已删除工作流继续占用名称，避免恢复冲突。历史版本和运行快照不改写。
- 评估后保留文件持久化，不引入 SQLite；新增操作指南，明确备份与迁移边界。

## 操作入口

左侧“管理”处理批量操作；点击“状态报告”查看实时状态；拖动两侧细分隔线调整布局。
详细说明：[操作指南](OPERATIONS.md)。

57 项回归测试通过，含 6 项新增名称与并发边界测试。
浏览器验证了 Session 管理、归档 / 恢复、Task 切换、重名前后端拦截、
拖拽和刷新恢复、键盘调整、390 / 768 / 1000 / 1100px 布局。
动态状态、权限等待、断连和减少动态效果通过隔离响应测试验证，没有为 UI 测试启动 Coding 任务。

已有工作流、Sessions、代码产物和原生 Gateway 保留。
个别旧 Session 的原生接口返回 404 时，工作台保留最后快照并显示同步原因；不会因此自动删除或伪造运行成功。

持久化仍采用现有版本文件、写入锁与快照校验，不提供新增的跨文件事务或灾难恢复保证。
SQLite 元数据层留待多用户并发、大量查询或多项元数据原子更新的需求出现后再引入。

## 上一轮：Workflow Library PoC

日期：2026-10-08。范围：`kirocrew-app-poc` 工作台改进。
这是本地 PoC 的交付记录，不是 KiroCrew 上游版本发布。

### 本次新增

- 工作流包含多个 Session 的导航树，Session 内查看运行 Tasks。
- Session 勾选、批量导出、工作台归档和恢复。
- 工作流删除 / 恢复；保留版本及历史 Session。
- “编辑工作流”统一入口。
- 三步向导：目标、任务与 Agent、确认。
- 每个任务内集中配置 Task ID、任务说明、Coding Tool、Model 和 Effort。
- Task ID 校验及完整运行身份展示，长文本换行。
- JSON / YAML / Markdown 导入导出。导入创建独立草稿，避免覆盖同名流程。
- 基于用户意图，通过 KiroCrew 原生 Chat 生成工作流草稿。
- Session 导出包新增开发手册、Release 候选记录、对话和 Feature 输入。
- 保存产品需求与设计决定，补充架构及交接流程图。

### 延续的行为

- 已启动 Session 固定配置版本，之后的修改用于下一次运行。
- 多 ACP 后端由现有 KiroCrew Gateway / SubagentManager / Provider Factory 接口承接。
- 权限、认证继续由 KiroCrew 与具体 Coding 工具处理。
- 不以 Agent 自述证明后端身份；请求值与实际报告分别展示。
- 原生模型不匹配时停止交接；未报告的 Effort 不推测。
- 旧 Kiro CLI PoC、原 Pipeline、已有运行和 Session 保留。

### 使用方式

打开 Workflow Studio：

1. 在左侧选择工作流下的 Session，跟踪任务进度。
2. 点击“编辑工作流”，在任务页同时配置任务与 Agent。
3. 在目标页导入 / 导出文件，或输入意图生成新草稿。
4. 保存新版本，再建立新 Session。
5. 勾选 Session 可导出或归档；归档页可恢复。

- 浏览器已验证任务 / Agent 合并、重复 Task ID 拦截、YAML 导入、
  Markdown 导出、工作流删除 / 恢复、Session 归档 / 恢复。

### 限制

- 归档是工作台管理标记，不关闭原生对话，不中断正在运行的开发。
- 生成需要现有 KiroCrew Gateway、Kiro CLI 登录与必要权限；不替用户自动批准。
- 生成草稿默认自动模型，具体模型 / Effort 仍需确认。
- Codex 完整动态模型目录、逐模型 Effort 筛选尚未接通。
- 会话包使用原生 Layer A 导出；不主动携带工具私有 Layer B。
- 导出是执行证据整理，尚未完成任务不会标记为发布完成。
- 当前支持 1–8 个顺序任务，未扩展为通用 DAG 调度器。
